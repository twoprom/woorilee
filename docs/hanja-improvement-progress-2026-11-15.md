# 한자 추천·변환 개선 실행 기록

기준 계획서는 `docs/plans/hanja-improvement-reassessment-2026-10-20.md`이다. 이번 기록은 구현과 검증 결과를 구분한다. 독립 언어 평가와 호스트 앱 검증이 끝나기 전에는 전체 계획의 완료나 정확도 목표 달성을 선언하지 않는다.

## 구현한 변경

- 앱과 새 `assoc app-verify` 평가 모드가 같은 top-3 분석 함수와 후보 패널 정렬 함수를 사용한다. 기존 평가 모드는 보존했다.
- 평가 결과에는 UTF-16 대상 범위, 실제 분절, 전체 후보, 점수 구성, 패널 순위, 실제 자동 변환 값과 보류 사유를 기록한다.
- 자동 미리보기는 강한 선택 prior에 추가하지 않는다. 사용자가 선택한 후보를 확정하면 prior에 기록하며, 자동 확정은 문맥 어휘와 기존 prior의 경과 시간에만 반영한다. 확정한 한글 유지 선택은 이전 한자 prior를 지우고, 취소는 prior를 변경하지 않는다.
- 수동 조회는 대상 양옆에서 각각 최대 200 UTF-16 단위의 문맥을 요청하고, 호스트가 넓은 범위를 반환해도 대상 구간을 제외한다. 조회 실패 시 기본 후보와 세션 이력만 사용한다. 기존 수동 조회에서 얻은 후보 목록을 유지하므로 문맥 조회를 이유로 후보를 새로 생성하지 않는다.
- 수동 경계 조정은 마지막 자동 분석의 문맥을 재사용한다. 병합한 범위와 겹치는 원래 분절들의 자기 제외 피처를 교집합으로 결합하고, Kiwi를 다시 실행하지 않는다. 반복 신축에도 원래 자동 분석을 유지한다.
- 후보 패널은 사용자가 탐색하기 전에는 미리보기를 강조하고, 탐색한 뒤에는 후보 식별자로 선택과 페이지를 복원한다.
- 입력 원문을 출력하던 로그를 길이와 범위로 바꿨다. 단계별 시간 계측도 원문을 기록하지 않는다.
- `유약:釉藥`, `음사:音寫`를 검증한 뒤 사전에 추가했다. 근거는 `eval/hanja-improvement-2026-11-15/dictionary-provenance.md`에 기록했다. 빈도·설명·연관 가중치를 임의로 추가하지 않았다.
- 사용자가 제출한 73행 검수를 반영한 후, 출처로 확인한 `비선:秘線`, `천도:遷道`도 추가했다. 전체 1,105행에서 자동 변환·보류·대상 분절은 이전과 같다. 사전 후보 목록은 15행에서 늘었다.
- 한 번의 동기 분석 안에서 읽기별 후보를 재사용한다. 캐시는 분석이 끝나면 버리므로 다음 키 입력에는 최신 사용자 사전과 선택 횟수가 적용된다.
- 기본 가중치가 0인 문자 공유 축에서는 문자 집합을 만들지 않는다. 양수·음수 사용자 지정 가중치와 자기 제외 동작은 유지한다.
- 재정렬할 때 형태소의 범위와 피처 문자열을 한 번 준비하고, 분절마다 자기 범위를 제외한 뒤 중복을 제거한다. 같은 단어가 대상 밖에 다시 나오는 경우도 기존과 동일하게 문맥에 남긴다.

정확도·보류 비교는 독립 검수 전의 잠정 진단이다. `policy-comparison-final.json`에는 실제 자동 변환 값 기준의 정밀도, 올바른 자동 변환 비율, 읽기별 macro와 Wilson 95% 구간을 함께 기록했다. 점수 차이를 확률로 표시하지 않는다. 기존 D2와 v1/v2는 이미 오류 분석과 보정에 사용했으므로 새 일반화 성능을 입증하지 못한다.

### 사용자 독립 검수 반영

제출한 `hanja-independent-review.tsv`의 ID·읽기·문장은 중립 시트와 73행 모두 일치했다.
장목의 `U / 長木`과 재주의 한글·`才操` 동시 허용은 대화에서 확인한 뒤 별도 파일에 기록했다.
원본과 기존 AI 라벨은 보존하고 `human-review/after-dictionary/labels.tsv`에 정규화한 판정을 저장했다.
U 65행, M 2행, K 3행, `?` 3행이며, M 중 재주 1행은 한글도 허용하므로 한자 필수 분모에서 제외한다.

한자 변환이 필요한 66행의 후보 1위 정답은 44행, 상위 3개 포함은 59행이다. 올바른 자동 변환은
32/66행이다. 채점 가능한 실제 자동 변환 44행 중 정답은 32행이며 정밀도는 72.7%이다.
U/M의 잘못된 자동 변환은 10행, K의 잘못된 자동 변환은 2/3행이다. 엄격한 보류 대안은 정답 자동
변환을 20행으로 줄이며 정밀도도 71.4%이므로 채택하지 않았다. 기존 test 44행이 포함된 개발
진단이어서 임계값을 이 표본에 맞추거나 일반화·99% 목표 달성을 주장하지 않는다.

검수 및 전후 평가의 출처·해시, 행별 오류와 점수는 `eval/hanja-improvement-2026-11-15/human-review/`
아래에 보존했다. 자세한 결과는 `human-review/REPORT.md`에 있다. 재주의 `才操` 허용 판정은 보존했지만,
현대 읽기 매핑을 확인할 1차 사전 근거가 아직 없어 `재주:才操` 항목 추가는 보류했다.

성능 파일은 분석 단계와 전체 키 처리를 구분한다. 추가 최적화는 각각 같은 실행 파일·입력·리소스를 사용해 순서를 바꾼 전후 3회씩 비교했다. 각 회차의 1,105행에서 후보 순위·점수·자동 변환 값·보류 사유가 모두 같았다.

- `performance-char-share/summary.json`: 0 가중치의 문자 공유 계산을 생략하니 해당 비교 회차의 장문 재정렬 p95가 4.14ms에서 2.43ms로 줄었다.
- `performance-feature-cache/summary.json`: 문맥 피처 준비와 중복 제거를 재사용한 다음 비교 회차에서는 장문 재정렬 p95가 0.584ms에서 0.483ms로 줄었다. 문자 공유 생략은 양쪽 실행 파일에 이미 적용되어 있다.
- 회차 사이에 시스템 속도가 크게 달라졌으므로, 첫 회차의 4.14ms와 마지막 회차의 0.483ms를 직접 비교한 개선율은 계산하지 않는다. 다른 빌드·테스트 작업이 없는 비교 회차 안에서의 결과를 사용한다. `quiet-performance.json`은 추가 최적화 전의 기록으로 보존한다.

최종 피처 재사용 비교에서 얻은 수치는 다음과 같다. 첫 행의 준비 시간을 제외하고, 짧은 문장은 50 UTF-16 단위 이하 376행, 긴 문장은 728행을 각각 3회 반복했다. 각 칸은 p50 / p95 / p99이며 단위는 ms이다.

| 입력 | 재정렬: 변경 전 | 재정렬: 변경 후 | 전체 분석: 변경 전 | 전체 분석: 변경 후 |
| --- | --- | --- | --- | --- |
| 짧은 문장 | 0.052 / 0.136 / 0.179 | 0.045 / 0.123 / 0.160 | 0.791 / 1.472 / 1.897 | 0.814 / 1.493 / 1.890 |
| 긴 문장 | 0.205 / 0.584 / 0.790 | 0.172 / 0.483 / 0.696 | 1.900 / 3.557 / 4.756 | 1.898 / 3.505 / 4.553 |

이 Release 오프라인 표본에서는 재정렬 p95 1ms 목표를 충족했다. 전체 분석 시간에는 호스트 IPC·이벤트 디스패치·패널 표시가 포함되지 않으므로 전체 키 지연으로 해석하지 않는다. 설치한 Debug 입력기의 호스트별 지연은 아직 검증하지 못했다.

`segmentation-compare`는 동일한 top-3 결과와 앱에서 사용하는 분절 생성기를 사용해 현재 정책과 분석 점수 우선 대안을 비교한다. 현재 정책은 936행, 대안은 931행에서 정확한 대상 범위를 찾았다. 대안에서 새로 찾은 대상은 0행이고 잃은 대상은 5행이다. 전체 분할이 달라진 행은 137행이다. 현재 정책의 대상 범위 결과는 앱 평가와 1,105행 모두 같았다. 이 수치만으로 품사·의미 정확도를 단정하지 않고 현재 앱 정책을 유지한다.

현대 산문 검수 후보는 [행정안전부 자료](https://www.korea.kr/news/policyNewsView.do?newsId=148975104), [재정경제부 자료](https://www.korea.kr/news/policyNewsView.do?newsId=148975484), [외교부 자료](https://www.korea.kr/briefing/pressReleaseView.do?newsId=156789245)에서 각각 짧은 문장 하나를 확보했다. 모두 계획서 작성 후 공개된 자료이며, 대상 읽기는 확인한 기존 평가·개발·보정 자료 24개에 없었다. `modern-holdout-sources.json`에는 출처·날짜·해시·겹침 감사 범위와 제한을 기록했다. 아직 정답을 부여하거나 채점하지 않았으며, 세 문장만으로 현대 산문을 대표하거나 일반화 성능을 입증할 수 없다.

## 사용자가 확인할 사항

1. 73행 검수는 제출받아 반영했다. `?`로 남긴 기정·사술·후수는 확인 가능한 때 보완하면 된다. 현재 평가를 위해 임의로 정답을 정할 필요는 없다.
2. 독립적인 일반화 평가에는 개발에 쓰지 않은 현대 산문과 해당 문장의 의미 판정이 추가로 필요하다. 73행 재검수만으로 새 일반화 성능을 선언하지 않는다.
3. 설치된 입력기로 Safari·TextEdit·Terminal에서 조합/확정, Backspace·Space·Return·Escape·Tab·화살표, 선택 영역 수동 변환, 조합 중 수동 변환, Shift+←/→, 후보 페이지 이동을 확인한다. 문장이 중복되거나 사라지는지와 확정 위치가 맞는지도 확인한다.

## 빌드·테스트 상태

- 독립 검수 반영 후 Python 검증·채점 테스트 8개와 앱 관련 Debug 회귀 테스트 7개가 통과했다. 기존 AI 정책 지표도 전부 이전과 같았다. 사전 보완 후 1,105문장의 분절·자동 변환·보류 값이 이전과 같은 것을 확인했다. 아래 전체 345개 검사는 이 사전 후속 변경 이전의 실행이다.
- 후속 Debug 빌드와 입력기 설치를 완료했다. 설치된 89개 파일이 빌드 결과와 같으며, 사전 해시와 시스템 서명 검사도 통과했다. 실제 호스트 입력 검증은 계속 남아 있다.
- 추가 최적화와 새 회귀 검사를 포함한 최종 Release 전체 테스트 345개가 한 번에 모두 통과했다. 이전 343개 실행에서 발생했던 R2 성능 검사 실패도 이번 전체 실행에서는 발생하지 않았다. 이전 결과는 `validation.json`의 이력으로 보존한다.
- 각 최적화의 관련 Debug 검사는 각각 35개와 43개가 모두 통과했다. 문자 공유 가중치의 양수·0·음수 경우와 반복 단어의 범위 제외 후 중복 제거를 명시적으로 검사한다.
- 앞선 Debug 검사에서 입력 이벤트·범위·문맥 조회·사전 추가·후보 보존·사용 이력·경계 조정·확정/취소 관련 128개 테스트가 모두 통과했다.
- 일반 테스트 명령은 처음에 앱과 테스트 번들의 서명 Team ID 차이로 실행에 실패했다. 검증할 때만 `CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM= ENABLE_HARDENED_RUNTIME=NO`를 적용했다. Release 검사에는 `ONLY_ACTIVE_ARCH=YES ENABLE_TESTABILITY=YES`도 사용했다. 프로젝트의 배포 서명 설정은 변경하지 않았다.
- 설치용 Debug 빌드에는 `/tmp/woorilee-improvement-install-20261115`를 DerivedData 옵션으로 지정했다. Xcode 설정에 따른 실제 앱 출력 경로는 `DerivedData/Build/Products/Debug/woorilee.app`이다. 빌드가 이전 테스트 PlugIns를 제거한 것을 확인했고, 원래 개발 서명과 hardened runtime 설정으로 빌드했다.
- TextEdit 제어가 허용되지 않아 실제 호스트 입력 검증은 수행하지 못했다. 별도 승인 요청으로 작업을 중단하지 않고 사용자가 확인할 절차를 위에 남겼다.
- 검증 요약과 결과 번들 경로는 `eval/hanja-improvement-2026-11-15/validation.json`에 기록했다. 설치된 앱의 89개 파일이 빌드 결과와 모두 같고 테스트 번들이 없는 것을 확인했다.


설치 후의 개발 서명은 시스템 신뢰 서비스에 접근하여 `codesign --verify --deep --strict`로 검증했고 통과했다. 제한된 샌드박스에서 수행한 첫 검증은 인증서 신뢰 접근 오류를 반환했으므로 해당 결과를 서명 실패로 단정하지 않았다.

검수 화면은 TSV와 같은 중립 73행만 표시한다. 문장별 판정·주정답·허용 후보·유보 사유를 입력하고 TSV로 내보낼 수 있다. 입력·이동·상태 복원·TSV 내보내기 로직은 검증했으나 화면 배치는 실제 브라우저로 검사하지 못했다. 원래 검수 TSV도 계속 사용할 수 있다.
